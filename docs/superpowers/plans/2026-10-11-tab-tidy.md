# tab-tidy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 重複タブを統合し、未分類タブをタブグループへ分類する処理を、操作していないときに定期実行する Firefox 拡張機能を作る。

**Architecture:** `core/` はブラウザ API に依存しない純粋関数で、計画（Plan）を作るのと、実行直前の再検証を担当する。`services/` はブラウザ API、LLM、storage とのやり取りを担当する。`orchestrator` はブラウザに依存する部分を `RunDeps` として注入で受け取るので、偽物を渡してテストできる。

**Tech Stack:** TypeScript, WXT（Manifest V3、Firefox 向けビルド）, Vitest（WXT の `WxtVitest` プラグインと `wxt/testing` の `fakeBrowser`）, tldts（登録ドメインの判定）, npm

**Spec:** `docs/superpowers/specs/2026-10-11-tab-organizer-design.md`

## Global Constraints

- 最低対応バージョンは Firefox 139: `browser_specific_settings.gecko.strict_min_version: "139.0"`
- 権限: `tabs`, `tabGroups`, `alarms`, `idle`, `storage`, `notifications`, `sessions`。LLM 接続先は `optional_host_permissions: ["http://*/*", "https://*/*"]` に宣言し、`permissions.request` で実行時に許可を求める
- LLM に送るのはタブのタイトルと URL だけ。送信先は利用者が設定した `llm.baseUrl` だけ
- 対象にするのは `http:` / `https:` のタブだけ
- 設定の初期値（spec §6）: `dedupe.mode=auto`, `dedupe.acrossWindows=false`, `grouping.mode=suggest`, `llm.enabled=false`, `llm.baseUrl=http://localhost:11434/v1`, `llm.model=""`, `llm.timeoutSeconds=30`, `schedule.intervalMinutes=30`, `schedule.idleSeconds=60`
- 実行ロックの失効は 5 分。実行履歴は直近 20 件。LLM に送るタブは 1 回あたり最大 50 枚
- 利用者に見える文言は日本語
- アラーム名は `tab-tidy-run`

## Review Focus

1. **計画を作った後に閉じられた、または移動されたタブ**: 提案を数時間後に適用しても、例外を出さずにそのタブを飛ばす → Task 3 の `revalidate` テストと Task 9 の orchestrator テスト
2. **LLM の応答が JSON 以外の文章や ```json コードブロックで囲まれている**: 囲みの中の JSON を取り出して使い、取り出せなければドメイン分類に切り替える → Task 7 の `parseAssignments` テスト
3. **IP アドレスや `localhost` のタブ**（tldts が登録ドメインを返さない）: ホスト名をそのままグループのキーにし、例外を出さない → Task 4 のテスト
4. **同じ URL のタブがすべて対象外（表示中・ピン留め）**: 閉じる計画を作らない。対象外のタブは「残すタブ」にも「閉じるタブ」にも数えない → Task 3 のテスト
5. **元に戻す対象が、Firefox の「最近閉じたタブ」に残る上限（25 件）を超えた**: 見つからない分は `tabs.create` で URL から開き直す → Task 8 の `undoLog` テスト
