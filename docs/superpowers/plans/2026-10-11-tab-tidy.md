# tab-tidy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Firefox extension that, while the user is idle, periodically merges duplicate tabs and sorts ungrouped tabs into tab groups.

**Architecture:** `core/` holds pure functions with no browser API dependencies; they build plans and do the re-validation right before execution. `services/` talks to browser APIs, the LLM, and storage. The `orchestrator` receives its browser-dependent parts injected as `RunDeps`, so tests can pass fakes.

**Tech Stack:** TypeScript, WXT (Manifest V3, Firefox builds), Vitest (WXT's `WxtVitest` plugin and `fakeBrowser` from `wxt/testing`), tldts (registrable domain lookup), npm

**Spec:** `docs/superpowers/specs/2026-10-11-tab-organizer-design.md`

## Global Constraints

- Minimum supported version is Firefox 139: `browser_specific_settings.gecko.strict_min_version: "139.0"` (later raised to 140; see the spec)
- Permissions: `tabs`, `tabGroups`, `alarms`, `idle`, `storage`, `notifications`, `sessions`. The LLM endpoint is declared in `optional_host_permissions: ["http://*/*", "https://*/*"]` and requested at runtime with `permissions.request`
- Only tab titles and URLs are sent to the LLM, and only to the user-configured `llm.baseUrl`
- Only `http:` / `https:` tabs are in scope
- Setting defaults (spec §6): `dedupe.mode=auto`, `dedupe.acrossWindows=false`, `grouping.mode=suggest`, `llm.enabled=false`, `llm.baseUrl=http://localhost:11434/v1`, `llm.model=""`, `llm.timeoutSeconds=30`, `schedule.intervalMinutes=30`, `schedule.idleSeconds=60`
- The run lock expires after 5 minutes. Run history keeps the last 20 entries. At most 50 tabs are sent to the LLM per request
- User-facing text is in Japanese
- The alarm name is `tab-tidy-run`

## Review Focus

1. **Tabs closed or moved after a plan was made**: applying a suggestion hours later skips those tabs without throwing → `revalidate` tests in Task 3 and orchestrator tests in Task 9
2. **LLM response wrapped in prose or a ```json code block**: extract and use the JSON inside; if none can be extracted, fall back to domain classification → `parseAssignments` tests in Task 7
3. **Tabs on an IP address or `localhost`** (tldts returns no registrable domain): use the hostname as the group key and never throw → tests in Task 4
4. **Every tab with the same URL is excluded (active or pinned)**: produce no close plan. Excluded tabs count as neither "kept" nor "closed" → tests in Task 3
5. **Undo covers more tabs than Firefox keeps in "recently closed" (25)**: reopen the missing ones from their URL with `tabs.create` → `undoLog` tests in Task 8
